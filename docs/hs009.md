# hs009 — ExceptT と IORef の組み合わせの学習

## 概要

`ExceptT`（`Control.Monad.Except`、`mtl`パッケージ）と `IORef`（`Data.IORef`、`base`）を組み合わせて使うための最小構成のパッケージ。
他のサブプロジェクト（hs001〜hs008）のコード・型・語彙は流用せず、独立している。
依存は `base` と `mtl` のみ。

題材は銀行口座。残高を `IORef Int` で持ち、入金・引き出し・送金といった「途中で失敗しうる操作」を `ExceptT BankError IO` で表す。
hs008 では状態を `State` で持ったが、ここでは状態を `IORef`（IO の中で書き換える参照）で持つ。
そのため **ExceptT で中断しても、それまでの IORef の書き換えは取り消されない**。この性質と、`catchError` で元に戻す方法を学べる。

## 実行方法

```sh

```

引数は取らない。3 つの口座（alice=100、bob=0、carol=0）に対して固定の操作を順に実行し、結果と各口座の残高を表示する。

```
$ hs009
--- initial ---
  alice=100 bob=0 carol=0
--- transfer alice -> bob 30 ---
Right ()
  alice=70 bob=30 carol=0
--- withdraw bob 50（残高不足） ---

  alice=70 bob=30 carol=0
--- payAll alice [bob 50, carol 50]（2 件目で失敗。1 件目は残る） ---

  alice=20 bob=80 carol=0
--- withRollback で包む [carol 10, bob 50]（1 件目は成功、2 件目で失敗。全部戻す） ---
Left (InsufficientFunds 10 50)
  alice=20 bob=80 carol=0
```

## IORef の基本

`IORef a` は、IO の中で読み書きできる「書き換えられる箱」。

```haskell
newIORef     :: a -> IO (IORef a)             -- 初期値を入れた箱を作る
readIORef    :: IORef a -> IO a               -- 中身を読む
writeIORef   :: IORef a -> a -> IO ()         -- 中身を書き換える
modifyIORef' :: IORef a -> (a -> a) -> IO ()  -- 関数で書き換える（正格）
```

- 同じ `IORef` を複数の場所で持っていれば、どこかで書き換えると全員から変わって見える（`State` のように状態を引き回す必要が無い）
- `modifyIORef`（`'` なし）は遅延評価で未評価の式（サンク）を溜めやすいので、数値の更新には `modifyIORef'` を使う
- 読み書きはすべて `IO` の操作なので、`ExceptT BankError IO` の中では `liftIO` で持ち上げて使う

```haskell
balance :: Account -> BankM Int
balance acc = liftIO (readIORef acc)
```

## `Bank` モジュール

```haskell
data BankError
  = InvalidAmount Int          -- 0 以下の金額を指定した
  | InsufficientFunds Int Int  -- 残高が足りない（残高, 引き出そうとした額）

type Account = IORef Int
type BankM   = ExceptT BankError IO

newAccount   :: Int -> IO Account
balance      :: Account -> BankM Int
deposit      :: Account -> Int -> BankM ()
withdraw     :: Account -> Int -> BankM ()
transfer     :: Account -> Account -> Int -> BankM ()
payAll       :: Account -> [(Account, Int)] -> BankM ()
withRollback :: [Account] -> BankM a -> BankM a
runBankM     :: BankM a -> IO (Either BankError a)
```

- `deposit` / `withdraw` は、金額が 0 以下なら `InvalidAmount` で中断する
- `withdraw` は残高が足りなければ、**書き換える前に** `throwError (InsufficientFunds 残高 額)` で中断する。そのため失敗しても残高は変わらない
- `transfer` は `withdraw` してから `deposit` する。引き出しで失敗すると、入金は実行されない
- `payAll` は複数の相手に順に `transfer` する。途中で失敗すると以降は実行されないが、**それまでの送金は残る**
- `withRollback` は、実行前に指定した口座の残高を控えておき、失敗したら `catchError` で捕まえて残高を戻し、同じエラーを `throwError` で投げ直す

## ExceptT で中断しても IORef は戻らない

`ExceptT` の `>>=` は、`Left` になった時点で後続を実行しないだけで、**すでに実行した IO の効果を取り消す機能は無い**。
IORef の書き換えは IO の効果なので、失敗する前に書き換えた分はそのまま残る。

```
payAll alice [(bob, 50), (carol, 50)]   -- alice=70 bob=30 から
  transfer alice bob 50    → 成功：alice=20 bob=80   （IORef を書き換えた）
  transfer alice carol 50  → 失敗：InsufficientFunds 20 50
結果：Left (InsufficientFunds 20 50)、残高は alice=20 bob=80 carol=0 のまま
```

途中の書き換えをまとめて取り消したいときは、`withRollback` のように自分で戻す。

```haskell
withRollback accs m = do
  saved <- liftIO (mapM readIORef accs)          -- 実行前の残高を控える
  m `catchError` \e -> do
    liftIO (zipWithM_ writeIORef accs saved)     -- 失敗したら戻す
    throwError e                                  -- エラーは呼び出し側へ伝える
```

## 状態の持ち方による違い

状態をどこに持つか、モナドをどの順に重ねるかで、失敗したときに状態がどうなるかが変わる。

| 組み合わせ | 失敗したときの状態 | 例 |
|---|---|---|
| `ExceptT e IO` ＋ `IORef` | 失敗するまでの書き換えが**残る** | hs009 |
| `ExceptT e (State s)` | 失敗するまでの状態が**残る**（`runState (runExceptT m)` が `(Left e, s)` を返す） | hs008 |
| `StateT s (Either e)` | 状態は**捨てられる**（`runStateT m s` が `Left e` だけを返す） | — |

## 補足

- `catchError` / `throwError` が扱うのは、`ExceptT` の `Left` だけ。`IO` の例外（`throwIO` や `error`、ファイルが無いなど）は別の仕組みで、`catchError` では捕まえられない（`Control.Exception` の `catch` などを使う）
- 複数のスレッドから同じ `IORef` を書き換えるときは、`atomicModifyIORef'` や `MVar`・`TVar`（STM）を使う。STM なら、途中で失敗したときの取り消しも自動で行われる
