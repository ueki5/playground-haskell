# hs007 — Stateモナドの学習

## 概要

Stateモナド（`Control.Monad.State`、`mtl`パッケージ）の使い方を学ぶための最小構成のパッケージ。
他のサブプロジェクト（hs001〜hs006）のコード・型・語彙は一切流用せず、完全に独立している。

`runState` / `evalState` / `execState` の使い分けを一通り学べる。

## Stateモナドの基本

`Control.Monad.State` は「暗黙に引き回す可変っぽい状態」を扱うためのモナド。

```haskell
type State s a  -- s: 状態の型, a: 計算結果の型

get    :: State s s          -- 現在の状態を取得
put    :: s -> State s ()    -- 状態を置き換える
modify :: (s -> s) -> State s ()  -- 状態を関数で更新する
gets   :: (s -> a) -> State s a   -- 状態の一部を取り出す

runState  :: State s a -> s -> (a, s)  -- 計算結果と最終状態の両方
evalState :: State s a -> s -> a       -- 計算結果だけ
execState :: State s a -> s -> s       -- 最終状態だけ
```

内部的には `State s a` は `s -> (a, s)`（状態を受け取り、結果と次の状態を返す関数）のラッパーであり、
`>>=` がその「状態の受け渡し」を自動でつないでくれる。状態を手で引数として引き回す代わりに、
`do` 記法で自然に書けるのがモナドのご利益。

```haskell
-- Stateモナドなしで書いた場合（状態を手で引き回す）
push :: Int -> [Int] -> ((), [Int])
push x s = ((), x : s)

-- Stateモナドを使った場合（Stack.hsの実装）
push :: Int -> StackM ()
push x = modify (x :)
```

## `Stack` モジュール

```haskell
type StackM a = State [Int] a

push    :: Int -> StackM ()
pop     :: StackM (Maybe Int)
peek    :: StackM (Maybe Int)
isEmpty :: StackM Bool

runStackM  :: StackM a -> (a, [Int])
evalStackM :: StackM a -> a
execStackM :: StackM a -> [Int]
```

- `push` は `modify (x :)` で状態（スタック）の先頭に値を積む
- `pop` は `get` でスタックを覗き、空なら `Nothing`、そうでなければ `put` で残りを新しい状態にして先頭を返す
- `peek` は `gets` で状態を読むだけ（状態は変更しない）
- `isEmpty` も `gets null` で読み取り専用
- `runStackM` / `evalStackM` / `execStackM` はいずれも初期状態 `[]` から実行するラッパーで、
  `runState` / `evalState` / `execState` が「結果と状態の両方」「結果だけ」「状態だけ」を
  それぞれ返すことに対応している

```
ghci> runStackM (push 1 >> push 2 >> pop)
(Just 2,[1])
ghci> evalStackM (push 1 >> push 2 >> pop)
Just 2
ghci> execStackM (push 1 >> push 2 >> pop)
[1]
```

## `lift` を使った例（`StateT` + `IO`）

`push` / `pop` / `peek` / `isEmpty` は `StackM`（`State [Int]`）専用ではなく、
`MonadState [Int] m => m a` という型で書かれている。

```haskell
push :: MonadState [Int] m => Int -> m ()
pop  :: MonadState [Int] m => m (Maybe Int)
```

`State [Int]` はもちろん、`StateT [Int] IO` も `MonadState [Int]` のインスタンスなので、
同じ `push` / `pop` を `StateT [Int] IO` の中でもそのまま呼び出せる。
`StateT [Int] IO` は「状態 `[Int]` を持ち回りつつ `IO` もできる」モナドで、
`lift :: IO a -> StateT [Int] IO a` を使うと `putStrLn` のような内側の `IO` アクションを
`StateT` のブロックに持ち上げて `do` 記法の中に混ぜられる（`app/Main.hs` の `program2`）。

```haskell
program2 :: StateT [Int] IO (Maybe Int, Maybe Int)
program2 = do
  push 1
  lift $ putStrLn "pushed 1"
  push 2
  lift $ putStrLn "pushed 2"
  a <- pop
  lift $ putStrLn ("popped: " ++ show a)
  b <- pop
  lift $ putStrLn ("popped: " ++ show b)
  pure (a, b)
```

`State` の実行に `runState` / `evalState` / `execState` があったように、
`StateT` にも `runStateT` / `evalStateT` / `execStateT` があり、いずれも `IO` の結果を返す
（`runState` が `(a, s)` を返すのに対し、`runStateT` は `IO (a, s)` を返す）。

```
$ hs007
...（省略。`program` の実行結果に続けて表示される）
pushed 1
pushed 2
popped: Just 2
popped: Just 1
Result2: (Just 2,Just 1)
Final stack2: []
```

## テスト方針

| describe | 主なテスト内容 |
|---|---|
| `push` / `pop` | LIFO順で値が返ること、`push` が状態の先頭に積まれること |
| 空スタックへの操作 | `pop` / `peek` が `Nothing`、`isEmpty` が `True` になること |
| `peek` / `isEmpty` | `peek` が状態を変更しないこと、`push` 後に `isEmpty` が `False` になること |
| `runStackM` / `evalStackM` / `execStackM` | 同じプログラムに対し、結果と状態の両方・結果だけ・状態だけをそれぞれ取得できること |
