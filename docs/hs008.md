# hs008 — ExceptTモナド変換子の学習

## 概要

`ExceptT`（`Control.Monad.Except`、`mtl`パッケージ）を使ったエラー処理を学ぶための最小構成のパッケージ。
他のサブプロジェクト（hs001〜hs007）のコード・型・語彙は流用せず、独立している。
依存は `base` と `mtl` のみ。

題材は逆ポーランド記法（RPN）の電卓。`"3 4 + 2 *"` のような式を、`Int` のスタックを状態として評価する。
0除算・スタック不足・不明なトークンといった「途中で失敗しうる計算」を `ExceptT` で表し、
`throwError` / `catchError` / `runExceptT` の使い方と、`State` と重ねたときの振る舞いを学べる。

## ExceptTの基本

`ExceptT e m a` は「内側のモナド `m` の計算に、型 `e` のエラーで中断する機能を足す」モナド変換子。

```haskell
newtype ExceptT e m a = ExceptT (m (Either e a))

runExceptT :: ExceptT e m a -> m (Either e a)  -- 中身の m (Either e a) を取り出す

throwError :: e -> ExceptT e m a                -- エラーを投げて以降の処理を打ち切る
catchError :: ExceptT e m a -> (e -> ExceptT e m a) -> ExceptT e m a  -- エラーを捕まえて回復する
```

（`throwError` / `catchError` は実際には `MonadError e m` 型クラスのメソッド。上は `ExceptT` に特化した型。）

`>>=` は、前の計算が `Left e` なら後続を実行せずにそのまま `Left e` を返す。
そのため `case` で `Either` を毎回調べなくても、`do` 記法で「成功した場合の処理」だけを書ける。

```haskell
-- ExceptTなしで書いた場合（Eitherを手でチェックする）
binOp f s = case pop s of
  Left e -> Left e
  Right (y, s1) -> case pop s1 of
    Left e -> Left e
    Right (x, s2) -> ...

-- ExceptT（+ State）を使った場合（Calc.hsの実装）
binOp f = do
  y <- pop
  x <- pop
  r <- f x y
  push r
```

内側のモナドが不要なときは `Except e = ExceptT e Identity` と `runExcept` も使える。

## `Calc` モジュール

```haskell
data CalcError
  = DivByZero           -- 0 で割った
  | StackUnderflow      -- 値が足りないのに pop した
  | UnknownToken String -- 数値でも演算子でもないトークン
  | InvalidResult [Int] -- 最後にスタックに値がちょうど1つ残らなかった

type CalcM = ExceptT CalcError (State [Int])

push      :: MonadState [Int] m => Int -> m ()
pop       :: (MonadState [Int] m, MonadError CalcError m) => m Int
safeDiv   :: MonadError CalcError m => Int -> Int -> m Int
evalToken :: (MonadState [Int] m, MonadError CalcError m) => String -> m ()
evalRPN   :: (MonadState [Int] m, MonadError CalcError m) => String -> m Int

runCalcM :: CalcM a -> (Either CalcError a, [Int])
calc     :: String -> Either CalcError Int
```

- `pop` は空スタックのとき `Maybe` を返すのではなく `throwError StackUnderflow` で計算全体を失敗させる
- `safeDiv` は除数が 0 なら `throwError DivByZero`
- `evalToken` は `+ - * /` なら2つ `pop` して演算結果を `push`、数値なら `push`、それ以外は `UnknownToken`
- `evalRPN` は全トークンを処理したあと、スタックに値がちょうど1つ残っていればそれを結果とし、そうでなければ `InvalidResult`
- `runCalcM` は初期スタック `[]` から実行し、結果（`Either`）と最終スタックの両方を返す
- `calc` は結果だけを返すラッパー

```
ghci> calc "3 4 + 2 *"
Right 14
ghci> calc "1 0 /"
Left DivByZero
ghci> runCalcM (evalRPN "5 1 0 /")
(Left DivByZero,[5])
```

## 変換子を重ねる順序

`CalcM` は `ExceptT CalcError (State [Int])` で、`ExceptT` が外側、`State` が内側。
`runCalcM` の型を展開すると、重ねる順序の意味がわかる。

```haskell
runExceptT :: ExceptT e (State s) a -> State s (Either e a)
runState   :: State s (Either e a) -> s -> (Either e a, s)
```

結果は `(Either e a, s)` なので、**エラーで中断しても、その時点までの状態は残る**。
`"5 1 0 /"` では `/` が `0` と `1` を `pop` したあと `DivByZero` で止まるため、最終スタックは `[5]` になる。
（同じ理由で、`"1 0 /"` の最終スタックは `[1,0]` ではなく `[]` になる。）

逆に `StateT [Int] (Either CalcError)` と重ねた場合は次のようになる。

```haskell
runStateT :: StateT s (Either e) a -> s -> Either e (a, s)
```

結果は `Either e (a, s)` なので、**エラーになると状態も一緒に失われる**。
どちらが良いかは用途次第で、「失敗した時点の状態を調べたい」なら前者、
「失敗したら何もなかったことにしたい」なら後者を選ぶ。

## `catchError` と `liftIO` を使った例（`ExceptT` + `StateT` + `IO`）

`Calc` の関数は `CalcM` 専用ではなく、`MonadState [Int] m` と `MonadError CalcError m` の制約で書かれている。
`ExceptT CalcError (StateT [Int] IO)` も両方のインスタンスなので、同じ関数をそのまま使える。
`app/Main.hs` の `program` では、各トークンの処理後にスタックを表示しつつ、
`DivByZero` だけを `catchError` で捕まえて `0` を積み直し、計算を続けている。

```haskell
program :: ExceptT CalcError (StateT [Int] IO) Int
program = do
  mapM_ step (words "10 2 / 0 /")
  pop
 where
  step tok = do
    evalToken tok `catchError` recover
    s <- get
    liftIO $ putStrLn ("  " ++ tok ++ " -> " ++ show s)
  recover DivByZero = do
    liftIO $ putStrLn "  (DivByZero を捕まえたので 0 を積む)"
    push 0
  recover e = throwError e   -- それ以外のエラーは投げ直す
```

- 変換子が2段以上重なると、`lift` を何回重ねればよいかを意識する必要がある。
  `liftIO` は、何段重なっていても一番内側の `IO` までまとめて持ち上げてくれる
- `catchError` のハンドラで `throwError` し直すと、そのエラーは外側にそのまま伝わる
- 実行は内側から順にほどく：`runStateT (runExceptT program) []` の結果は `IO (Either CalcError Int, [Int])`

なお、`where` 句のローカル関数 `step` / `recover` には型シグネチャを付けている。
省略すると型推論で `MonadState [Int] m` という制約が推論され、
Haskell2010では `FlexibleContexts` 拡張なしに受け付けられずにコンパイルエラーになるため。

## テスト方針

| describe | 主なテスト内容 |
|---|---|
| `calc`（正常系） | 四則演算が正しく評価され、`-` と `/` でオペランドの順序が守られること |
| `calc`（エラー系） | `DivByZero` / `StackUnderflow` / `UnknownToken` / `InvalidResult` がそれぞれ返ること |
| `ExceptT e (State s)` の性質 | 最初のエラーで処理が打ち切られること、中断してもそれまでのスタックが残ること |
| `catchError` | エラーを捕まえて別の値で続行できること、エラーの種類で分岐できること |
